# NODO Rescue

Первое обновление поддерживает закрытый legacy NODO: отсутствие процессов/писателей, terminal Tasks, целостная история с завершёнными turns. Живой legacy без drain не убивается. Независимые службы не участвуют в lifecycle; backup ограничен NODO profile и явным bridge/observer allowlist. Passive bridge-watch разрешён по pinned исходникам/launchd args/telegram:false. Это не заявление о наличии drain в legacy.

Production installer сохраняет состояние com.nodo-optional.dsh-watchdog и scheduled NODO runner com.nodo-optional.vk-factoscope; временно выгружает их только без активной работы. Для нового совместимого NODO используются pause/drain/quit; для закрытого legacy проверяется cold state. После установки и health DSH_BRIDGE_RESTART меняется на stable installed launcher. Guardian восстанавливает loaded state и незавершённую конфигурационную миграцию; других jobs не касается.

Согласованный encrypted snapshot содержит полный профиль NODO и точные bridge/observer state files (BackupScope.swift). Shared roots независимых служб исключены. Используется уже созданный NODO Backup/Recovery Keychain account из update.json, ключ в пакет не входит. Restore только в новый каталог. Post-install health и сохранность данных обязательны; renderer ready сам по себе не означает успех.

Независимое macOS-приложение на Swift/AppKit. После сборки использует только системные библиотеки; NODO, Node, DSH и node_modules ему не нужны. `node rescue/build.cjs` нужен только разработчику для компиляции.

Кнопки: обычный запуск, Safe Mode, диагностика/детерминированный ремонт, откат, журналы, диагностический пакет, изолированная копия для внешнего Codex.

Установка: `scripts/update-manifest.cjs release` создаёт команды установки/отката. Установщик проверяет процессы по точным путям кода/данных, открытые файлы данных и незавершённые Tasks, SHA256 исходной версии и нового bundle. При изменении исходного кода после подготовки установка блокируется. Копия предыдущего кода создаётся непосредственно при установке. Новая версия ставится в `~/Applications/NODO.app`; история в `~/Library/Application Support/NODO` не копируется и не откатывается. Для первой legacy-версии исходный runtime копируется внутрь backup bundle и `rc-location.json` перенаправляется на установленный bundle. Нужен запас диска для новой версии и резервной копии runtime.

Резервные версии и журнал установки: `~/Library/Application Support/NODO Rescue`. Откат сохраняет неудачный bundle рядом с backup, проверяет целостность backup и возвращает только код. Отдельный rollback требует idle. При startup failure установщик сообщает ошибку, оставляет backup и доступный откат.

Первая legacy-копия сохраняет исходный `app.asar` побайтно как `legacy.asar`; маленький `Resources/app` bootstrap загружает его исходный `main.cjs`. Только вызов точного DSH bin получает последний `legacy-overlay.json`: старый `rc-workstation` отключён, вместо него используется extension из backup/installed bundle. Это устраняет зависимость от старого symlink в пользовательском web-профиле без изменения самого профиля. Внутренний runtime symlink относительный; DSH использует bundled Node, скопированный из подготовленного релиза. Остальные spawn-вызовы не изменяются. ASAR entry проверяется до преобразования, неподдерживаемая структура останавливает установку до замены приложения.

Успешный запуск: свежий `startup-status.json`, `state: ready` и PID запущенного процесса; предел ожидания 45 секунд. Safe Mode использует `NODO_SAFE_MODE=1` и отдельный `NODO Safe Mode` userData. Для восстановленной legacy-версии без startup marker проверяется принадлежащий ей DSH listener и HTTP 200. Legacy не поддерживает Safe Mode.

Integrity manifest schema 2 включает хэши файлов, список файлов и цели symlink. Генерировать после `codesign --deep`, затем подписать только верхний app. Из custom hash исключены `_CodeSignature`, сам manifest и точный основной executable из Info.plist, потому что codesign меняет Mach-O. Rescue всегда требует `codesign --verify --deep --strict`: основной executable и manifest защищены подписью bundle. Тестовые приложения тоже подписываются; обхода через manifest нет. Ad-hoc подпись подтверждает целостность, но не происхождение релиза от доверенного издателя.

Диагностика сохраняет версии, integrity, состояние запуска, PID/порты, проверку JSON и счётчики фиксированных категорий ошибок из хвоста логов. Не экспортирует сырой stdout/stderr, crash report, текст ошибок, чаты или credentials. Поэтому необычная ошибка может потребовать локального просмотра журналов. Детерминированно исправляется подтверждённый stale Electron lock: hostname совпадает, PID не существует, писателей нет; symlink сохраняется в карантин. Если код повреждён/отсутствует или установка неполная, Diagnose & Repair автоматически возвращает проверенный backup последнего обновления: совпадают target/data, фаза prepared/installed, целостность backup подтверждена, процессы/открытые файлы/активные Tasks отсутствуют. До ремонта сохраняется диагностический пакет; история и конфигурация не откатываются. При отсутствии валидного backup остаётся диагностика/repair copy. Произвольные caches/config/locks автоматически не удаляются.

AI repair: кнопка готовит полную отдельную копию app bundle с Electron/runtime и ограниченную диагностику в `Documents/Codex/NODO-Repair-*`; в копии устанавливается `build-mode.json: dev`, пересоздаются integrity manifest и подпись. Код исправляется внутри скопированного `Contents/Resources/project`; проверить запуск можно прямо из этого app без vendor/build scripts. Используется профиль NODO DEV, поэтому другой DEV должен быть закрыт. Внешний Codex пользователь открывает вручную; автоматическое создание AI-задачи и применение патча не реализованы. Это доступно даже при сломанном DSH; если сам packaged project потерян, остаётся backup/rollback. Legacy без поддержки dev-режима не запускается как repair copy. История/авторизации в repair workspace не копируются.

Проверка `node tests/rescue.cjs`: искусственные install/rollback, сохранение истории и новых файлов после update, отказ при drift, диагностика повреждения runtime и реального завершения startup-процесса с кодом 23. Тесты не используют основной NODO.
